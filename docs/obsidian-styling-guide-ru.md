# Как оформлять заметки в Obsidian
## Полное руководство по Markdown, семантическим классам и дизайн-системе ESDS

> **Главный принцип:** сначала смысл и структура заметки, затем визуальное оформление. Markdown отвечает за содержание и организацию материала, семантические классы — за смысл отдельных фрагментов, а палитра и стили ESDS — за внешний вид.

Это руководство описывает универсальный подход к оформлению учебных, справочных и рабочих заметок в Obsidian. Он не привязан к конкретному предмету или языку: одна и та же система подходит для английского, других языков, истории, науки, бизнеса и любых других тем.

Документ сверён с исходным кодом **English Study Design Studio 0.9.19**. В реестре этой версии — **30 коротких семантических классов `st-xx`**, включая добавленный в 0.9.18 класс `st-lt` для отдельных иностранных букв и коротких буквосочетаний.

## 1. Из чего складывается оформление заметки

В Obsidian можно сочетать несколько уровней оформления. Они решают разные задачи и не должны подменять друг друга.

| Уровень | За что отвечает | Когда использовать |
|---|---|---|
| Markdown | Структура и смысл документа | Всегда: заголовки, абзацы, списки, таблицы, ссылки |
| Семантические классы ESDS | Роль короткого фрагмента текста | Когда нужно обозначить термин, перевод, факт, акцент и т. п. |
| Callout | Отдельный смысловой блок | Для предупреждений, правил, примеров, советов и важных заметок |
| Палитра ESDS | Цветовая система всей заметки | Когда нужен цельный дизайн в светлом и тёмном режимах |
| Фон заметки | Атмосфера и поверхность документа | Когда нужен спокойный, текстурный или тематический фон |
| Стиль блоков | Геометрия и визуальное поведение блоков | Когда нужно изменить характер рамок, поверхностей и контейнеров |
| Тема Obsidian и CSS snippets | Внешний вид самого приложения и дополнительные правила | Для общей оболочки Obsidian или точечных расширений |

**Не нужно выбирать что-то одно.** Хорошая заметка может одновременно использовать Markdown, несколько семантических классов, пару Callout и палитру. Важно, чтобы каждый уровень выполнял свою функцию.

## 2. Markdown — основа документа

Markdown должен оставаться главным инструментом структурирования. Он прост, переносим, быстро редактируется на телефоне и не зависит от конкретной палитры.

### Заголовки

Используй последовательную иерархию:

```markdown
# Название заметки
## Основной раздел
### Подраздел
#### Деталь подраздела
```

Не перескакивай между уровнями без причины. Заголовок обозначает структуру, а не просто увеличенный или цветной текст.

### Абзацы и списки

Обычные объяснения оставляй обычными абзацами. Последовательности действий, признаки и перечисления оформляй списками.

```markdown
- Первый пункт
- Второй пункт
  - Уточнение
  - Ещё одно уточнение

1. Первый шаг
2. Второй шаг
3. Третий шаг
```

Не оборачивай каждый абзац в HTML. Это усложняет редактирование и мешает сохранять заметку чистой.

### Таблицы

Таблицы подходят для сравнений, классификаций, грамматики, характеристик и компактных справочников.

```markdown
| Понятие | Значение | Пример |
|---|---|---|
| Term | Термин | A useful term |
| Example | Пример | An example sentence |
```

Сама таблица остаётся Markdown. Если нужно выделить конкретный термин или перевод внутри ячейки, используй короткий семантический фрагмент. Не превращай каждую ячейку в отдельный HTML-блок.

### Цитаты и разделители

Цитаты оформляй Markdown-цитатой:

```markdown
> Короткая цитата или важная формулировка.
```

Разделитель `---` используй только там, где действительно меняется крупная часть материала. Не добавляй декоративные линии после каждого небольшого блока.

## 3. Семантические классы ESDS

Семантический класс сообщает, **какую роль выполняет фрагмент текста**. Он не задаёт предмет, язык или тему заметки. Палитра ESDS уже определяет, как этот класс выглядит.

Для коротких фрагментов используется HTML-обёртка `span`:

```html
<span class="st-te">ключевой термин</span>
```

Оборачивай только нужные слова или короткие выражения. Не оборачивай большие разделы, длинные абзацы, целые таблицы и списки.

### Важное различие: иностранное слово и отдельная буква

В системе есть два разных класса — их нельзя смешивать.

- `st-fo` — иностранное **слово или выражение**, независимо от языка.
- `st-lt` — отдельная иностранная **буква** или короткое буквосочетание из 2–3 букв.

Пример:

```html
<span class="st-lt">ñ</span>
<span class="st-lt">th</span>
<span class="st-fo">through</span>
<span class="st-pr">/θruː/</span>
<span class="st-tr">через</span>
```

Класс `st-lt` появился в ESDS 0.9.18. Для него предусмотрено собственное оформление и отдельный токен цвета `--esds-letter` с безопасным fallback. В 0.9.19 он входит в общий реестр классов.

### Как не перегружать текст

- Не выделяй каждое иностранное слово, если это не помогает учебной задаче.
- Не помечай одним классом целые абзацы, когда достаточно выделить термин.
- Не используй несколько классов на одном фрагменте без ясной причины.
- Не создавай новые коды вроде `st-english`, `st-grammar` или `st-history`.
- Не задавай цвета через inline CSS: внешний вид должен контролироваться палитрой.

## 4. Callout — оформление крупных смысловых блоков

Callout — это отдельный блок с заголовком и содержимым. В отличие от семантического класса, который выделяет небольшой фрагмент, Callout помогает визуально отделить целую мысль или группу связанных сведений.

Базовый синтаксис Obsidian:

```markdown
> [!important] Важно
> Это ключевое замечание, которое нужно запомнить.

> [!warning] Внимание
> Здесь указано ограничение или возможная ошибка.

> [!example] Пример
> Здесь приведён пример применения правила.
```

В универсальной инструкции ESDS предусмотрены стандартные типы:

| Тип | Для чего подходит |
|---|---|
| `important` | Важная информация |
| `warning` | Предупреждение или ограничение |
| `tip` | Совет или полезный приём |
| `info` | Справочная информация |
| `example` | Пример |
| `quote` | Цитата |
| `abstract` | Краткое содержание или обзор |

Используй Callout по смыслу, а не ради цвета. Не превращай каждый абзац в отдельную карточку. Вложенные Callout и длинные цепочки блоков обычно ухудшают чтение на небольшом экране.

**Палитра ESDS отвечает за визуальную согласованность Callout.** Цвета, рамки и другие визуальные детали не нужно вручную прописывать в тексте заметки.

## 5. Палитра ESDS — единый визуальный язык

Палитра — это не просто два-три акцентных цвета. Это согласованная система оформления всей учебной заметки.

Полноценная палитра должна учитывать:

- фон и поверхности заметки;
- основной, вторичный и приглушённый текст;
- заголовки и визуальную иерархию;
- ссылки и интерактивные элементы;
- смысловые классы ESDS;
- иностранные слова, отдельные буквы, переводы и произношение;
- Callout и их рамки;
- таблицы, цитаты, разделители и другие Markdown-компоненты;
- светлый и тёмный режимы;
- читаемость и контраст на Android.

### Light и Dark

У палитры должны быть две согласованные версии:

- **Light** — для светлого режима Obsidian.
- **Dark** — для тёмного режима Obsidian.

Тёмная версия не должна быть простой инверсией светлой. Цвета фона, текста и акцентов нужно подбирать отдельно, сохраняя узнаваемый характер палитры и достаточный контраст.

### Смысловые цвета

Цвет должен помогать распознавать роль информации. Например, иностранное слово, произношение и перевод могут иметь разные акцентные оттенки. Это особенно полезно в языковых заметках, но система остаётся универсальной: те же семантические роли работают в любом материале.

Не следует назначать один и тот же цвет всем акцентам или делать все элементы максимально яркими. Важна иерархия: главный акцент заметнее второстепенного, а обычный текст остаётся комфортным для длительного чтения.

### Категории палитр

В ESDS предусмотрены 18 визуальных направлений:

1. Светлые и воздушные
2. Пастельные
3. Цитрусовые
4. Фруктовые и ягодные
5. Конфетные и десертные
6. Сочные и тропические
7. Неоновые и электрические
8. Радужные и многоцветные
9. Цветочные и ботанические
10. Морские и водные
11. Природные и земные
12. Тёплые и солнечные
13. Космические и фантазийные
14. Тёмные и глубокие
15. Ретро, винтаж и поп-арт
16. Элегантные и премиальные
17. Игровые и мультяшные
18. Артистические и экспериментальные

Это направления визуального дизайна, а не предметные профили. Не нужно выбирать «английский», «историю» или «бизнес»: одна палитра должна работать с любым содержимым.

## 6. Фон заметки и стиль блоков

Палитра, фон и стиль блоков связаны, но это разные части оформления.

### Фон

Фон задаёт общее ощущение поверхности: чистый, спокойный, текстурный, природный или тематический. Он не должен мешать чтению, снижать контраст или отвлекать от текста.

### Стиль блоков

Стиль блоков отвечает за форму и подачу отдельных визуальных контейнеров: характер поверхностей, рамок, скруглений и других геометрических деталей.

В зависимости от выбранной палитры ESDS может автоматически использовать связанный с ней стиль блоков. Поэтому не нужно без необходимости отдельно подбирать независимый стиль после каждой смены палитры.

### Полный набор оформления

Если нужно переносить целую визуальную комбинацию, логичнее использовать полный набор, объединяющий палитру, фон и стиль блоков, а не пытаться вручную воспроизвести их по отдельности.

## 7. Тема Obsidian, CSS snippets и ESDS — не одно и то же

### Тема Obsidian

Тема изменяет внешний вид самого приложения: панели, меню, интерфейс редактора и другие элементы Obsidian. Она может влиять и на отображение заметок.

### CSS snippets

CSS snippets — дополнительные CSS-правила, которые пользователь подключает отдельно. Они подходят для небольших индивидуальных изменений, но требуют аккуратности: широкие селекторы могут затронуть не только нужную заметку, но и другие части хранилища.

### ESDS

ESDS предназначен для оформления учебной заметки через собственную систему дизайна. Его правила должны быть изолированы и не менять оформление остальных заметок и интерфейса Obsidian без необходимости.

**Практическое правило:** тему выбирай для приложения в целом, а ESDS — для согласованного оформления содержимого заметок. Не используй глобальный CSS-сброс ради локального эффекта.

## 8. Рекомендуемый порядок оформления новой заметки

1. Создай структуру Markdown: заголовок, разделы, абзацы, списки и таблицы.
2. Проверь, что материал логично организован и легко читается без цветов.
3. Добавь семантические классы к действительно важным коротким фрагментам.
4. Используй Callout для отдельных крупных блоков: предупреждения, правила, примера или вывода.
5. Примени палитру ESDS, которая подходит по визуальному характеру.
6. При необходимости выбери фон и стиль блоков.
7. Проверь заметку в светлом и тёмном режимах, а также на экране телефона.
8. Убери лишние акценты, если оформление начинает конкурировать с содержанием.

### Небольшой пример

```markdown
# Present Simple

## Когда используется

<span class="st-te">Present Simple</span> — время, которое обычно описывает привычки, регулярные действия и общеизвестные факты.

> [!example] Пример
> I work every day.

- <span class="st-fo">usually</span> — <span class="st-tr">обычно</span>
- <span class="st-fo">always</span> — <span class="st-tr">всегда</span>
- <span class="st-fo">never</span> — <span class="st-tr">никогда</span>

> [!important] Главное правило
> В третьем лице единственного числа к смысловому глаголу обычно добавляется окончание **-s** или **-es**.

<span class="st-wa">Не путай форму глагола после he / she / it с формой после I / you / we / they.</span>
```

Пример показывает сочетание Markdown, коротких семантических фрагментов и Callout. Палитра ESDS определяет цвета и визуальные детали.

## 9. Чего лучше не делать

- Не строить всю заметку из HTML-контейнеров, если достаточно Markdown.
- Не использовать inline CSS для цветов, фонов, рамок и размеров.
- Не придумывать предметные или языковые CSS-классы.
- Не выделять каждую строку, термин или предложение без смысловой причины.
- Не превращать все абзацы в Callout.
- Не использовать яркие цвета вместо структурной иерархии.
- Не применять глобальные CSS-правила, способные изменить другие заметки.
- Не менять вручную Properties и YAML только ради визуального эффекта.
- Не считать автоматическую проверку исходников заменой проверке реального отображения в Obsidian Android.
