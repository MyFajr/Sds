## 1. Общие сведения

### 1.1. Что это за продукт

ESDS — плагин визуального оформления заметок для изучения языков в Obsidian. Плагин
поставляет семантическую дизайн-систему: палитры, фоны заметок, стили блоков (Callout),
семантические классы (`st-fo`, `st-te`, `st-tr` и др.) и полноценный GUI «Design Studio»
для выбора, настройки, импорта/экспорта и применения оформления к заметке через
`cssclasses` во frontmatter.

### 1.2. Как работает плагин (архитектура по результатам аудита)

| Компонент | Файл/строки | Назначение |
|---|---|---|
| Данные палитр | `main.js:7–132` | 3 встроенные палитры (roles, dark, callouts, calloutFrames) |
| Генерация CSS | `makePaletteCss`, `makeBlockStyleCss` | CSS-переменные на лету для пользовательских элементов |
| Библиотека пользователя | `loadUserLibrary` / `saveUserLibrary` (`main.js:4066+`) | `data.json` плагина + миграция legacy-файла |
| Применение к заметке | `applySelected` (`main.js:2990`) | запись классов в `cssclasses` через `processFrontMatter` |
| Локальные стили заметки | `refreshNoteStyles`, `updateNoteStyleCss` | маркер `<!--ESDS:...-->` + кэш per-note CSS |
| Отключение стилей Callout | `setCalloutStylesDisabledForFile` | DOM-опция на открытые view + MutationObserver |
| GUI | `DesignStudioModal` (`main.js:1662`) | аккордеон-секции, каталог с папками/поиском/ленивой подгрузкой, избранное, недавние |
| Дочерние модалки | `PreviewModal`, `LibraryItemPreviewModal`, `PaletteBuilderModal`, `BackgroundBuilderModal`, `CategoryManagerModal`, `NoteBlockStyleModal` | предпросмотр, конструкторы, тонкая настройка |
| Команды | `main.js:4000–4002` | ribbon-иконка, 2 команды (открыть студию, экспорт библиотеки) |

Сценарий пользователя: лента → «Design Studio» → выбор палитры (фон наследуется, блоки
подбираются автоматически) → «Применить к заметке» → классы `esds-note`,
`esds-palette-*`, фон, `esds-blocks-*`, `esds-frames-from-palette` пишутся в
`cssclasses` активной заметки.

- ✅ Синтаксическая целостность: `node --check main.js` — без ошибок; баланс скобок CSS — 0.
- ✅ Честная миграция legacy-библиотеки с очисткой старой папки.
- ✅ Защита от повторного срабатывания (`_removeDesignPromise`, debounce `_catalogSearchTimer`, батчинг `_refreshGeneratedStylesTimer`).
- ✅ Ленивая подгрузка каталога (`catalogPageSize: 24`) и дебаунс поиска (180 мс).
- ✅ Базовая клавиатурная навигация на карточках (`role="button"` + Enter/Space).
- ✅ Корректная выгрузка: таймеры, MutationObserver, style-узлы удаляются в `onunload`.

- ✅ Мобильный-first: `dvh`, `env(safe-area-inset-*)`, медиазапросы.

### 2.2. Найденные проблемы

**Категория A — UX/интеракция**

| # | Проблема | Серьёзность |
|---|---|---|
| A1 | Полный ре-рендер контента модалки после любого клика (аккордеон, вкладки, сортировка, «Дополнительно») **сбрасывает фокус** — с клавиатуры невозможно последовательно раскрыть несколько секций | Высокая |
| A2 | Аккордеон: при открытии тематическая иконка подменяется стрелкой `▾`, при закрытии — `›`; шеврон не вращается, а подменяется текстом — нет визуальной непрерывности | Средняя |
| A3 | Раскрывающиеся секции появляются «мгновенно» (display:none→block), без перехода; ощущение «дёрганого» интерфейса | Средняя |
| A4 | Кнопки без hover/active-отклика: нет переходов, нет «нажатия», липкая кнопка в футере не приподнята визуально | Средняя |
| A5 | Нативные `select` (сортировка) не стилизованы и выбиваются из дизайн-системы | Низкая |
| A6 | Нет стилизованного скроллбара для скролл-областей модалок (на Windows/desktop выглядит по-умолчанию грубо) | Низкая |

**Категория B — доступность (a11y)**

| # | Проблема | Серьёзность |
|---|---|---|
| B1 | У аккордеонных триггеров нет связки `aria-controls` ↔ `id` панели | Средняя |
| B2 | `:focus-visible` есть только у части карточек (`.esds-button`, 3 вида карточек); у полей ввода, селектов, вкладок каталога, заголовков групп, «Дополнительно» — нет | Средняя |
| B3 | У групп избранного список скрывается через `hidden`, но нет `aria-controls`/`id` связки | Низкая |
| B4 | Анимации не полностью закрыты `prefers-reduced-motion` (есть только 2 локальных блока) | Низкая |

**Категория C — согласованность и технический долг**

| # | Проблема | Серьёзность |
|---|---|---|
| C1 | Шапка `styles.css` гласит «0.5.5» при версии плагина 0.9.19 — рассинхрон версий | Низкая |
| C2 | `styles.css`: 4080 строк, 415 `!important`, дублирующиеся медиазапросы одинаковых брейкпоинтов — накопленный долг за итерации 0.5.x → 0.9.x | Долг (не трогаем в этой итерации) |
| C3 | Нет README с инструкцией по установке и скриншотами | Долг |
| C4 | Параметры сортировки каталога (`sortModes`) живут только в памяти модалки — сбрасываются при каждом открытии | Низкая (зафиксировано как будущая работа; требует расширения схемы data.json) |

### 2.3. Ответ на вопрос «что не хватает»

Функционально плагин покрывает полный цикл. Не хватает именно **отделки и доступности**:
плавности раскрывающихся окон, обратной связи кнопок, фокус-состояний для клавиатуры и
скринридеров, единой версии. Это и есть объём работ v0.9.20.

## 3. Требования к версии 0.9.20

### 3.1. Функциональные требования (обязательные)

1. **FR-1.** После клика по триггеру аккордеона, вкладке каталога, переключателю
   «Дополнительно» фокус после ре-рендера возвращается на инициировавший элемент.
2. **FR-2.** Шеврон аккордеона — один глиф, состояние раскрытия передаётся CSS-поворотом;
   тематическая иконка секции отображается всегда.
3. **FR-3.** Панель аккордеона связана с триггером через `id` + `aria-controls`; то же для
   групп избранного.
4. **FR-4.** Существующее поведение (применение, сброс, удаление оформления, каталог,
   избранное, конструкторы, импорт/экспорт) не изменяется. Никакие функции не удаляются.

### 3.2. Требования к дизайну (обязательные)

1. **DR-1.** Плавное появление панели аккордеона (fade + slide, ≤ 200 мс).
2. **DR-2.** Hover-подсветка и «press»-отклик (масштаб ≤ 0.98) для всех `.esds-button`.
3. **DR-3.** Приподнятая тень липкого футера.
4. **DR-4.** Стилизованный `select` в едином стиле (кастомная стрелка, `appearance: none`).
5. **DR-5.** Стилизованный тонкий скроллбар для скролл-областей.
6. **DR-6.** Все изменения — добавляющим «polish-слоем» в конце `styles.css` (без правки
   4000 строк существующих правил) чтобы исключить регрессии.

### 3.3. Требования к доступности (обязательные)

1. **AR-1.** Единое `:focus-visible` кольцо для всех интерактивных элементов модалок
   (кнопки, инпуты, селекты, вкладки, `role="button"`, `[tabindex="0"]`).
2. **AR-2.** Глобальный guard `prefers-reduced-motion` для анимаций модалок студии.

### 3.4. Версионирование

1. **VR-1.** `manifest.json` → `0.9.20`; `versions.json` += `"0.9.20": "1.5.0"`.
2. **VR-2.** Шапка `styles.css` синхронизирована с версией релиза.

### 3.5. Ограничения

- Не переписывать `styles.css` (консолидация — отдельная задача, см. §5).
- Не менять схему `data.json` (персистентность сортировки — отдельная задача).
- Не добавлять новые зависимости. Совместимость: Obsidian ≥ 1.5.0, desktop + mobile.

## 5. Дополнительные требования импорта/экспорта v0.9.20

- ZIP manifest name имеет приоритет при автозаполнении новой категории; если manifest отсутствует, используется имя ZIP-файла.
- Отмена выбора/подтверждения не должна оставлять пустую категорию в библиотеке.
- ZIP-палитры с `schemaVersion: 4`, создаваемые экспортом ESDS, должны приниматься импортом.
- Дубликаты по ID или названию пропускаются; частично выполненный ZIP-импорт откатывается к исходной библиотеке.
- Ручная проверка ZIP import/export на Android WebView обязательна перед выпуском.
